# FITBOX BLE Lab

次の実装用：[エクササイズモニタへの引き継ぎ](docs/fitness-monitor-handoff.md)

実測結果：[センサーの取り付け方向・回転数・時刻の分析](docs/fitbox-sensor-analysis.md)

アプリ構想の調査：[現実の街を走るアプリの実現性・技術構成](docs/virtual-cycling-feasibility.md)

MacのChrome向け、FITBOX-03807 / CSC (0x1816, 0x2A5B) の検証アプリ。外部ライブラリ・クラウド接続は不要です。Python 3でローカル配信します。

## 起動

このフォルダで `npm run dev` または `python3 -m http.server 5173 --bind 127.0.0.1` を実行し、Chromeで http://localhost:5173 を開きます。

1. nRF Connectやサイクリングアプリの接続を切断し、MacのBluetoothをオンにします。
2. ペダルを動かしてセンサーを起こし、「センサーに接続」からFITBOX-03807を選びます。
3. 初回の通知を基準として、2回目以降の回転差からrpmを計算します。
4. 「計測をリセット」後、基準となる通知を待ち、ペダルを10回まわしてWheel / Crankの増分を比較します。
5. 「JSONを保存」で受信ログをダウンロードします。再読み込み前に保存してください。

見つからない場合は接続設定の「デバイス名で絞らず選択する」を試してください。ChromeへのBluetoothアクセス許可が必要な場合があります。

## データの意味と限界

- センサーの累積回転数と、センサー時刻 (1/1024秒単位・64秒周期) を表示します。累積値は運動開始時のゼロとは限りません。
- Wheel / Crankを別々に解析します。Wheel rpmはペダルrpmとは限らず、実機で対応関係を確かめてください。
- 16/32ビット回転カウンターと16ビット時刻の桁あふれに対応します。64秒以上の受信間隔や明らかな不連続は再基準化しますが、センサーリセットと桁あふれの完全な識別はできません。
- 5秒以上回転の更新がなければrpmを空欄にします。停止と受信欠落は区別できず、低速回転では更新なしになることもあります。
- 再接続後は新しい通知を基準とし、切断中の回転は計測に加えません。
- 電池残量はBattery Serviceがある場合に表示します。表示するサービス一覧はブラウザに許可した3種類の範囲です。
- 画面に最新100件、ダウンロードに最新10,000件を保持します。生データ・受信時刻も保存します。
- 実機でのBluetooth接続は手元のMacで確認してください。ブラウザを前面にして検証することを推奨します。
